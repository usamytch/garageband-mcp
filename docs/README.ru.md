# GarageBand MCP — версия для сведения

Локальный форк [visualfart/garageband-mcp](https://github.com/visualfart/garageband-mcp). В нём сохранены история и MIT-лицензия оригинала, MIDI-инструменты дополнены управлением микшером, перемещением регионов и экспериментальной автоматизацией громкости.

[Установка и подключение](../README.md#build-and-connect) · [Архитектура](architecture.md) · [Процесс сведения](mixing-workflow.md) · [Команды](tools.md) · [Проверки](testing.md)

## Возможности

- 70 MCP-команд. Для 52 команд требуется явный путь к сохранённому проекту.
- Очередь GUI-операций и общий локальный замок между экземплярами сервера.
- Дорожки, mute/solo, панорама, громкость с чтением фактических dB, доступные Smart Controls.
- Перемещение обычных аудио/MIDI-регионов по целым тактам и между совместимыми дорожками.
- Чтение дробных границ регионов: такт, доля, деление, тик в том виде, в котором их сообщает GarageBand. Пропущенные единицы остаются `null`; преобразование в секунды или абсолютные тики не предполагается.
- Явное включение и скрытие вида автоматизации с проверкой результата. Кривые при этом не меняются.
- Проверка стыков по каналам с точными координатами и защищёнными фразами; воспроизводимые рецепты стереомиксов, включая Intro 10/11.
- Экспорт отдельным процессом: журнал, статус, продолжение после обрыва и проверенное восстановление микшера. Существующие файлы не перезаписываются.
- Экспериментальные вокальные rides: небольшие изменения громкости на пустой видимой линии автоматизации в копии проекта 4/4. Результат обязательно проверяется экспортом и повторным открытием.

Доли/тики для перемещения регионов и произвольные параметры плагинов в Hz/ms/dB пока не реализованы. Smart Controls принимают нормализованные значения; это не физические единицы. Для GUI нужен разблокированный Mac и английский интерфейс GarageBand.

[Выделение фрагментов по атаке](attack-region-design.md) — проект следующего этапа, включая привязку аудио к шкале проекта и проверку разрезов экспортом.

## Скилл сведения

[Mix Engineer](../skills/mix-engineer/SKILL.md) — один общий процесс и шесть подключаемых профилей: панк, фанк, металл, поп, рок, латино. В профилях есть музыкальные ориентиры, условия применения, критерии сравнения и первичные источники. Латино пока опирается на Latin pop/reggaeton; сальса и бачата требуют отдельного уточнения ориентиров.

Скилл сначала фиксирует задачу, референсы и исключённые дорожки, затем создаёт план работы с копией проекта. После баланса — тональные правки и, если нужны, вокальные rides. Каждая существенная итерация заканчивается WAV, сравнением при одинаковой воспринимаемой громкости и записью результата. Исключённые дорожки остаются выключенными; удаление исходников не является обычным этапом сведения.

Проекты `.band`, записи, экспорты и рабочие журналы хранятся отдельно от Git. Сервер создаёт материалы проверки автоматизации, отчёты по стыкам, результаты рецептов и журналы экспорта. Музыкальные решения и слуховая оценка остаются за ассистентом и пользователем. Схемы и границы новых команд описаны в [audio-workflows.md](audio-workflows.md).

## Быстрый старт

```sh
git clone https://github.com/usamytch/garageband-mcp.git
cd garageband-mcp
npm ci
npm run check
```

Подключите `dist/index.js` к MCP-клиенту, используя абсолютные пути к Node и серверу. Установите папку `skills/mix-engineer` в каталог скиллов клиента.

Для проверки стыков и рецептов нужны FFmpeg/ffprobe и NumPy из `scripts/audio_edit/requirements.txt`. Переменная `GARAGEBAND_MCP_PYTHON` задаёт Python этого окружения. Полная локальная проверка — `npm run check:all` с тем же Python на `PATH`. Дальше можно попросить:

> Используй $mix-engineer. Сделай рок-микс на копии проекта, сохрани мои исключения, сравни результат с исходным WAV и отдельно проверь вокальную автоматизацию через экспорт.

Автоматические тесты проверяют код и протокол; живая проверка GarageBand требует отдельного тестового проекта. Подробнее — в [testing.md](testing.md).

## Сведение и вокал

`gb_mix_audio` измеряет громкость, пики и стерео/моно, обрабатывает отдельные WAV эквалайзером, компрессором, де-эссером и сатурацией, готовит проверенные по уровню A/B. `gb_vocal_process` анализирует высоту моновокала, сдвигает выбранные интервалы с явным алгоритмом и рендерит вокодер с заданными аккордами. Подробности и границы: [обработка микса](mix-processing.md), [вокал](vocal-processing.md). Это отдельные новые аудиофайлы; команды не заменяют плагины внутри GarageBand и не подтверждают качество на слух.
